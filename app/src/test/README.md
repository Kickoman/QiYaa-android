# `app/src/test/` — JVM-тесты

JUnit 4 без эмулятора: `./gradlew testDebugUnitTest`. Сетевые классы тестируются против `MockWebServer` на общих фикстурах из `spec/`, DSP — синтезированными сигналами. Имена тестов — предложения о поведении в обратных кавычках.

## Общие фикстуры (`spec/`)

Тесты API отдают mock-серверу ответы из `spec/fixtures/yandex/<endpoint>/<case>.json` и сравнивают разобранное с `spec/expected/yandex/<endpoint>/<case>.json` (формат — `spec/fixtures/yandex/README.md`, `spec/expected/yandex/README.md`). JSON-ответов внутри кода тестов нет.

| Файл | Содержит |
|---|---|
| `support/SpecFixtures.kt` | `Spec.fixture(endpoint, case)` — тело и HTTP-статус из имени случая (`401-…` → 401), `Spec.expected(…)`, `Spec.cases(endpoint)`; `Fixture.response()` для `MockWebServer` |
| `support/SpecJson.kt` | Android-модели → нейтральный JSON спеки. `Track` не хранит `albumTitle`, `year`, `genre`: они убираются с ожидаемой стороны, а `coverUri` сравнивается как URL, построенный `TrackParsing.coverUrl` |
| `support/FakeEngine.kt` | `queue.PlayerEngine` для тестов: плейлист, курсор, конец очереди, порядок shuffle по контракту `PlayerEngine` (`shuffle: HeadShuffle`; проход — сначала `lead`, затем остальная голова по возрастанию, чтобы тесты его знали; `insertTracks` ставит треки за соседом (`HeadShuffle.insertedAfter`), `appendTracks` — в конец (`inserted`); `shuffleOrder = …` задаёт голову; порядок меняется до колбэка, а `report` проверяет, что он той же длины, что плейлист), синхронные колбэки в `QueueController`, как у ExoPlayer, включая повтор всей очереди, `seekTo` на текущий индекс — только `onSeeked()`, `skipToNext` уводит из конца очереди (`isEnded = false`, позиция 0), с `pauseAtEndOfCurrent` `finishTrack()` не переходит дальше, а ставит `playWhenReady = false` и зовёт `onPausedAtEnd()` (и `onPlayingChanged(false)`, если контроллер не включил игру снова), вставку в пустой плейлист — `onItemChanged(NEW_QUEUE)`, позицию, перемотку по позиции (`seekToPosition` зовёт `onSeeked()`, как разрыв позиции ExoPlayer), «назад», паузу, причину перехода (`Transition`) и флаг «играет»; при удалении текущего трека сообщает переход, как ExoPlayer. Смена shuffle, повтора и паузы в конце (`pause at end true/false`) только пишется в журнал: контроллер эхо не слушает, выбор пользователя тесты дают через `controller.setShuffle`/`setRepeat`. Журнал команд `commands` |
| `support/FakeMusicSource.kt` | `queue.MusicSource` с ответами-лямбдами (в том числе отложенными через `CompletableDeferred`), журнал вызовов и отметок `/play-audio` |
| `support/QueueHarness.kt` | контроллер + фейки на виртуальном времени `runTest`, собранные события `events`, `track()`/`tracks()`; `attached = false` — контроллер без движка, `store` — сохранённая очередь; `continueWithVibe` — настройка «продолжать волной» для новых очередей, изменяемая (`var`), по умолчанию выключена, чтобы старые тесты коротких очередей кончались, как раньше; `wave(scope, ids)` — волна `S1`/`B1` из этих треков, поставленная, но ещё не заигравшая (тесты сами зовут `startPlaying()`) (`user:onyourwave`), догрузка которой никогда не отвечает |
| `support/NetworkLoss.kt` | два порядка, в которых ExoPlayer сообщает одну сетевую ошибку как `onPlayerError` и `onIsPlayingChanged(false)`: `ERR_01_ERROR_THEN_STOPPED` (ошибка во время игры: в одном обновлении сначала ошибка) и `ERR_03_STOPPED_THEN_ERROR` (кончился буфер, ошибка позже); тесты ERR-09 гоняют оба (`queue/README.md`, `/play-audio`) |
| `support/FakeQueueStore.kt` | `queue.QueueStore` в памяти: текст файла, число записей, `snapshot()` — разобранная очередь |

Путь к `spec/` передаёт Gradle: системное свойство `qiyaa.spec.dir` в `app/build.gradle.kts`, а файлы спеки объявлены входами задачи тестов, так что правка спеки перезапускает тесты. Без `git submodule update --init` тесты падают с подсказкой.

Расхождение с десктопом не подгоняется: тест пишется по спеке, помечается `@Ignore("Known divergence Kickoman/QiYaa-android#N: …")`, и на расхождение заводится задача. Сейчас таких тестов нет.

**Traps:**
- Тела ошибок из фикстур одних эндпоинтов используются как подставные для других: спека разрешает любой фикстуре ошибки стоять за любой эндпоинт.
- В `resolveTrackUrl` хост `storage.mds.yandex.net` из фикстуры подменяется адресом mock-сервера строковой заменой: сам JSON не меняется.
